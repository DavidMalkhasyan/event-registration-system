# EventFlow — что планировалось и что осталось

Этот файл отделяет **первоначальный план и идеи развития** от [реализованного объёма](ASSIGNMENT_SCOPE.md). Это не обещание реализовать всё перечисленное и не список незавершённых обязательных требований MadDevs.

## Первоначальный план

По [требованиям](REQUIREMENTS.md) и [первому плану этапов](docs/process/MILESTONES.md) предусматривались:

- **Основа:** отдельные React frontend и Node.js backend, PostgreSQL, миграции, тесты и CI.
- **Регистрация:** создание мероприятий, регистрация участника по email, подтверждение, ограничения вместимости, FIFO-лист ожидания и автоматическое продвижение.
- **Билеты и вход:** уникальный билет/QR, однократный check-in, сценарии одновременных регистраций, онлайн-счётчики.
- **Организаторы:** кабинет, управление мероприятием и участниками, роли сотрудников, сообщения и напоминания.
- **Дальнейшее расширение:** организации и администраторы, фотографии, место проведения и карта, работа с реальным почтовым провайдером, эксплуатационная инфраструктура.

Реализация этих пунктов и автоматические доказательства приведены в [ASSIGNMENT_SCOPE.md](ASSIGNMENT_SCOPE.md); хронология изменения приоритетов — в [KANBAN.md](docs/process/KANBAN.md), [POST_RELEASE_PLAN.md](docs/process/POST_RELEASE_PLAN.md) и [DEVELOPMENT_JOURNAL.md](docs/process/DEVELOPMENT_JOURNAL.md). Часть поздних расширений фактически реализована, несмотря на слово «post-release» в названии исторического плана.

## Что сознательно оставлено на следующий этап

| Направление | Следующий шаг / причина |
| --- | --- |
| Реальная почта | Настроить Resend с собственным подтверждённым доменом и проверить отправку и вебхуки на реальном аккаунте. Пока для демо используется fake provider. |
| Публичное развёртывание | Выбрать хостинг и домен, развернуть HTTPS, проверить мониторинг и восстановление на настоящем сервере. Шаблоны Docker/операций подготовлены, но публичного развёртывания нет. |
| Карты под нагрузкой | Для production выбрать поставщика карт либо собственные тайлы; бесплатные OSM-тайлы не предполагаются для высокой нагрузки. |
| Физические устройства | Проверить QR-сканирование на реальных телефонах/камерах; браузерные автоматические тесты не заменяют этот этап. |
| Межплатформенное демо | Отдельно проверить запуск Docker на Windows и macOS; автоматический smoke test проходит на Ubuntu. |
| Наблюдаемость и эксплуатация | Подключить реальные уведомления об отказах почты, мониторинг задержек worker и регулярные backup/restore-процедуры в целевой среде. |

## Что не планировалось добавлять без необходимости

Отдельный Redis, Kafka, Kubernetes и независимые микросервисы: для текущей нагрузки PostgreSQL и модульного монолита достаточно. Решение изменить архитектуру потребует результатов измерений, а не добавления технологий ради сложности.
