# Assignment Scope and Traceability

This file maps each assignment requirement to its implementation, its automated evidence and its status. It is the delivery scope for the submission. [REQUIREMENTS.md](REQUIREMENTS.md) (v1.7, "Proposed — awaiting stakeholder review") stays the authoritative, full product specification and is **not** changed by this file. Where the implementation is narrower than REQUIREMENTS.md, §4 says so explicitly.

**Status values:**

- **Not started**
- **In progress**
- **Implemented but unverified:** code exists, but no automated test proves it.
- **Tested:** an automated test that ran and passed proves it.
- **Verified:** for a non-functional requirement, a recorded run proves it (commands and results in the journal), but it is not part of the repository's test suite.
- **Deferred:** extended scope, intentionally not built.

## 4. Simplifications compared with the design documents

The design documents in `docs/` describe the full system: 27 tables and 52 operations. The submission implements a focused subset. Each simplification is also recorded as a process decision in [DECISION_LOG.md](docs/process/DECISION_LOG.md) (PD-10 onward).

1. **Schema:** 26 tables in 15 migrations with K-715 (K-715's `0015` widens a staff-session check; K-716's `0014` adds `organization_invitations`; K-712's `0013` adds `event_images`, metadata only; K-711's `0012` adds the optional venue to `events`; K-710's `0011` adds `platform_admins` and `platform_admin_sessions`; K-709's `0010` adds password and verification columns and widens checks; K-708's `0009` adds `organizations` and `organization_memberships`, [POST_RELEASE_SCHEMA.md](docs/database/POST_RELEASE_SCHEMA.md); K-703's `0008` widens two constraints; K-404b backfills cutoff tasks; K-304d adds `deletion_markers`; K-405 `rotation_requests`; K-406 `staff_invitations` and `staff_sessions`; K-305b the `registrations.removal_reason` column), instead of 27 tables in 10 migrations. Omitted: webhooks, provider events, delivery budget, reauthentication and related tables.
2. **API:** 40 HTTP API routes on `dev` (K-703 added the organizer cancellation route; 39 in the release; K-304a added the capacity route, K-304b the details edit, K-302b re-authentication, K-304c cancellation, K-304d the deletion preview and deletion, K-405 resend, share links and rotation, K-406 seven staff routes, K-306 check-in undo, K-305b waiting-list removal; counted from the route registrations on 2026-10-12, S-15; Fastify also answers `HEAD` for every `GET`), plus `/healthz` and the development-only `/dev/mailbox`, listed in [README.md](README.md) §7, instead of 52 operations. `openapi.yaml` still describes the full design, not this subset.
3. **Messages:** 15 of the 17 designed message types (K-304c added event cancellation; K-405 ticket resend and "management link replaced"; K-406 staff invitation; K-305b waiting-list removal): sign-in, verification, ticket, waiting list, existing access, promotion, reminder, event change, cancellation confirmation and, with K-404b, "waiting list closed".
4. **Outbox:** claim, freshness check, fenced send, reaper and sweeps are implemented. Not implemented: the delivery budget, pausing, webhooks, regeneration, and a re-check at render time.
5. **Decision time:** the design's database function `app.decision_time()` (FN-01) is replaced by an application-level helper that reads `clock_timestamp()` after the lock, plus a test-only offset.
6. **Test infrastructure:** ENG-TST-2 (Testcontainers) is replaced by a local PostgreSQL 18 test database, because no container runtime is installed. CI uses a `postgres:18` service container. Integration and E2E tests both recreate the `app` schema of the test database, so they must not run at the same time.
7. **Check-in roles:** the owner and invited staff (K-406). Staff devices have a dedicated entry, `staff.html` at `/staff` (PD-69, replacing PD-57's minimal page in the organizer entry), with no organizer code.
8. **Language:** English user interface and emails (OQ-8 is still open).

## 5. Verification levels and known limitations

| Level                                   | What it covers                                                                                                                                                                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tested (automated, real PostgreSQL)** | Every P0 feature in §1 and every P1 feature marked Tested in §3: 135 integration, 11 unit and 22 browser tests in CI. Concurrency claims (last seat, double check-in, races) are covered by forced-order and parallel tests.          |
| **Tested with simulated browser APIs**  | Camera scanning: `getUserMedia` returns a canvas stream (or a permission error) and `BarcodeDetector` reports the code the test holds up; everything after detection (staff session, endpoint, database, live count) is real (PD-74). |
| **Verified by a recorded manual run**   | Clean-clone setup (S-03, S-14); browser review of every screen at 1440, 768 and 390 px with real data (S-13); development-mode link handling (S-14). Recorded in the journal.                                                         |
| **Not verified**                        | Camera scanning on a physical phone or camera (accepted by the stakeholder as a documented limitation, PD-79); macOS and Linux desktops for the local setup; email gateways (AC-179).                                                 |
| **Deferred**                            | Email-address change (FR-ORG-6), link revocation lists, localization (OQ-8), Resend, webhooks, delivery budget and pausing, production deployment, performance testing, Redis.                                                        |

**Known limitations:**

- Only the fake email provider exists; no real email is sent.
- Event artwork is original CSS (PD-79). The v0 design's three AI-generated photographs, whose reuse rights were not established, were removed from the current tree in S-16; earlier commits still contain them.
- The Vite development server does not send the production page headers; the production path is the tested one (PD-71, PD-72).
- Accepted by design: browser history may keep a link's fragment (EC-97); email gateways may rewrite links (EC-98). AC-186 (c) has no automated test.
